# 类型 → 边界用例映射

从源文件的参数类型系统推导边界用例，避免遗漏。

## 映射表

| 类型 | 边界值 | 最少用例数 |
|---|---|---|
| `number` | `0`、`-1`、`MAX_SAFE_INTEGER`、`NaN`、`Infinity` | 5 |
| `string` | `''`（空）、超长（> 1000 字符）、特殊字符（`\n` `\0` emoji）、仅空白 | 4 |
| `boolean` | `true`、`false` | 2 |
| `T[]` / `Array<T>` | `[]`（空）、单元素、超大数组、含重复项 | 4 |
| `Record<K, V>` / 对象 | `{}`（空）、缺失必填字段、多余字段、字段为 `null` | 4 |
| `T \| null` / `T \| undefined` | `null` / `undefined` 本身 | 1（可与其他边界合并） |
| 联合字面量 / 枚举 | 每个合法值、一个非法值（类型断言绕过） | N+1 |
| `Promise<T>` | resolve、reject | 2 |
| 回调 / 函数参数 | 正常调用、抛错、不被调用 | 3 |
| `Date` | 无效日期 `new Date('invalid')`、边界时刻 | 2 |
| 泛型嵌套（如 `Map<string, T[]>`） | 外层空 + 内层空、外层有值内层空 | 组合 |

## 推导原则

**边界值优先于正常值数量。** 一个函数有 3 个参数时，不必为每个参数都写满边界——覆盖每个参数**最典型的一个**边界即可：数值取 0 与负数、字符串取空串、数组取空数组。

**组合爆炸要控制。** 两个参数各 4 个边界 = 16 组合，但只写其中 4–6 个代表性的即可。优先：

1. 全正常
2. 第一个参数异常 + 其余正常
3. 最后一个参数异常 + 其余正常
4. 全异常

**可选参数单独处理。** `fn(a: string, b?: number)` 需要覆盖 `b` 省略的情形。

## 类型不明确时

TypeScript 项目通常有显式类型。遇到 `any` / 推断类型时：

- 从调用方反推实际传入的类型
- 若仍不明确，按最宽假设（string | number）取边界，并在测试注释里标明假设

## 与业务约束的交互

类型边界是一层，业务约束是另一层。两者都写：

```ts
// 类型边界：空字符串
it('应在 name 为空时返回校验错误', () => { ... });

// 业务边界：超长但类型合法
it('应在 name 超过 50 字符时返回长度错误', () => { ... });
```

业务约束从源码的校验逻辑读取，不从类型推导。

## React 组件的"参数"

组件的 props 就是参数：

| props 类型 | 边界 |
|---|---|
| `children?: ReactNode` | 省略、空、多元素 |
| `disabled?: boolean` | 省略、true |
| 事件回调 | 省略、提供、验证调用次数 |
| 条件渲染的分支 | 每个分支至少一个用例 |
