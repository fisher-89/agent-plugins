# design.md 结构

描述**已存在**的代码架构，不提出新设计。目标读者是后续生成测试的人。

```markdown
# 设计: <change 名>

> **范围**: <本次补测试的模块清单或目录>
> **日期**: <YYYY-MM-DD>
> **类型**: 存量代码反构

---

## 架构组件

| 组件 | 职责 | 文件位置 | 依赖 | 技术 |
|------|------|----------|------|------|
| <组件名> | <一句话职责> | <相对路径> | <被谁依赖 / 依赖谁> | <框架、库> |

---

## 变更清单

> 本次补测试的源文件范围。

### 源文件

| 文件路径 | 说明 |
|----------|------|
| <path> | <该文件负责什么> |

### 公共函数 / API

只列模块级导出，不含私有函数。导出 class 的公开方法逐条列出。

| 标识符 | 所在文件 | 签名 | 说明 |
|--------|----------|------|------|
| <fnName> | <path> | `fnName(a: string, b?: number): Result` | <行为一句话> |
| <ClassName.method> | <path> | `method(x: T): Promise<void>` | <行为一句话> |

### 类型定义

| 类型名 | 所在文件 | 说明 |
|--------|----------|------|
| <TypeName> | <path> | <用途> |

## 关键行为与约束

描述对写测试有影响的既有行为：

- 错误处理方式（抛异常 / 返回 Result / 返回 null）
- 副作用（IO、网络、时间、随机）
- 状态依赖（单例、缓存、全局变量）
- 边界契约（空值、超长、非法输入时的既有表现）

---

## 不纳入范围

列出范围外但相邻的内容，避免后续误判：

- <path 或模块> — <为什么不在本次范围>
```

## 填写要求

| 要求 | 说明 |
|---|---|
| 路径相对项目根 | POSIX 风格（`/` 分隔） |
| 签名从源码读取 | 不凭记忆或推测填写，读文件确认参数类型与返回类型 |
| 中文叙述 | 标识符、路径、命令保持英文 |
| 只描述现状 | 不写"应该怎样"、"建议改为" |
| 不含测试内容 | 测试策略、用例设计属于 `test-design.md`，不在此出现 |
| 省略空子表 | 某子表无内容时整段省略，不留空表 |

## 签名格式

TypeScript：

```
function parseImports(file: string): Import[]
parseOptions(raw: unknown, defaults?: Options): Options
class Session { begin(turn: Turn): void; end(): Promise<Result> }
```

- 单行、不换行
- 可选参数用 `?`
- 泛型完整写出
- 联合类型用 `|`，不用 `|` 折行

## size 控制

`design.md` 是阶段 3 的输入，会被完整读取。控制在**可一次读完**的规模：

- 公共 API 表只列本次范围内的文件
- 关键行为每条一两句
- 不复制源码，不贴完整实现片段

若范围过大（源文件 > 20 个），建议在阶段 1 就与用户确认是否拆分为多次调用。

## 已存在时

`openspec/changes/<name>/design.md` 已存在时，向用户确认：

- **覆盖** → 按本次模块清单重写，然后进入阶段 3
- **沿用** → 不读不改，直接进入阶段 3；阶段 3 的用例设计以磁盘上的旧 `design.md` 为输入
