# test-design.md 结构

按**源文件**分节。每节的测试文件与源文件 colocated 一一对应——这是阶段 4 续跑的锚点，分节标题必须精确。

```markdown
# 测试设计: <change 名>

> **日期**: <YYYY-MM-DD>
> **范围**: <模块清单概览>

---

## 覆盖范围

| 源文件 | 测试文件 | 公共导出数 |
|--------|----------|------------|
| <src path> | <test path> | <n> |

---

## 单元测试

### <源文件> -> <测试文件>

#### 待测功能

- `fnName(a: string, b?: number): Result` — <一句话描述>
- `ClassName.method(x: T)` — <一句话描述>

#### 用例

| 测试对象 | 路径类型 | 测试条件 | 预期 |
|---------|----------|----------|------|
| <describe 标题> | 正向 | <it 标题：输入与预期> | <返回值 / 副作用> |
| <describe 标题> | 异常 | <非法输入与预期错误> | <抛错类型 / 错误码> |
| <describe 标题> | 边界 | <边界值与预期> | <返回值> |

#### Mock策略

| Mock主体 | Mock方案 | 应用场景 |
|---------|----------|----------|
| <模块 / 全局 / 环境> | <如何 mock，返回什么> | <哪些 describe 需要> |

### <下一个源文件> -> <测试文件>

（同上结构）

---

| 条目 | 原因 |
|------|------|
| <导出 / 行为> | <为什么无法或不必用单测覆盖> |
```

## 分节规则

| 规则 | 说明 |
|---|---|
| 一个源文件一节 | 标题 `### <源文件> -> <测试文件>`，路径均相对项目根 |
| 不设独立集成测试章节 | 跨模块组合用例挂靠到链路入口模块的那一节，`describe` 标题写链路方向 |
| 不合并多个源文件 | 合并会使续跑比对失效 |
| 顺序无关 | 生成时按节独立处理，不必与源文件在磁盘上的顺序一致 |

## 用例表

| 列 | 内容 |
|---|---|
| 测试对象 | `describe()` 的标题，同节内保持一致 |
| 路径类型 | `正向` / `异常` / `边界` |
| 测试条件 | `it()` 的标题，写清输入与预期 |
| 预期 | 返回值、抛错、副作用——用于生成断言 |

**覆盖要求**：`待测功能` 里列出的每个导出都至少被一行 `用例` 覆盖；每个 describe 尽量包含正向、异常、边界三类（不适用的类型可省，但需在 `不测试项` 说明）。

边界用例按 `edge-cases.md` 的类型映射推导。

## Mock策略表

| 列 | 内容 |
|---|---|
| Mock主体 | 被 mock 的东西：模块路径、全局对象、环境变量、时间 |
| Mock方案 | 具体做法（`vi.mock('./db', () => ...)`、`vi.useFakeTimers()`），以及返还的假值 |
| 应用场景 | 哪些 describe 需要这层 mock |

遵守 `mock-rules.md` 的最小 mock 原则：只 mock 进程边界与显式入参，内部模块之间的调用必须真实组合。

## 中文要求

- 叙述、表格内容、`describe` / `it` 标题：中文
- 标识符、路径、命令、框架名：英文
- 缩写（API、JSON、URL、CI）保持原样

## 不测试项

如实列出，不要为了"看起来完整"而编造。典型条目：

- 纯配置读取（无逻辑）
- 依赖外部服务且无法 mock 的行为
- 框架自身保证的行为（不重复测框架）
