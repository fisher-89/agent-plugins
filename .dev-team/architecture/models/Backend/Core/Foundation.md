# Backend.Core.Foundation

## 职能

工作区在磁盘上的目录布局只在这里算一次：把「根目录 + 各层目录名 + 报告槽位」拼成具体
路径；workspace 身份串（按工作区分库、分目录时的命名来源）也从同一份根目录派生。另有三项
判断跟路径同源，也放在这里——一个字符串是不是仓库内的相对路径、哪些目录属于依赖产物、
Windows 上哪些名字不能拿来当路径。取消的两半（可克隆共享的读端、只管置位的写端）也在这里：
它是唯一只依赖标准库的容身之处。

**边界**：不起子进程、不碰版本控制、不持数据库句柄、不读工作区配置、不带异步运行时。
依赖只有 SHA-256 hash 实现（只给身份串用），不依赖工作区内任何其它模块。

## 承载理由

- **不依赖工作区内任何模块，这是唯一的准入门槛**：它存在的意义是给依赖图留一个汇点——谁都
  可以依赖它，它不依赖谁，因此不可能绕出环来。凡是需要引第三方库才能做的事，不管有几个
  调用方，都不进这里：早先想把通配符匹配搬进来，就因为要引一个匹配库而被拒；外部依赖也只
  保留了一个哈希实现。「有人用第二次才搬下来」只回答「什么时候搬」，不回答「能不能进来」
  ——后者全看这一条。
- **目录名与文件名只写一次**：工作区布局用到的全部名字——`openspec` / `changes` / `archive`
  / `explores` / `reports` / `test` / `baseline` / `archi` / `.dev-team` / `architecture` /
  `models` / `graph` / `model` / `config.json`——各自只有一处定义。上层一律经本模块取路径，
  MUST NOT 自己拼：自己拼一处，目录改名就从「改一个常量」变成「全仓搜索」。`.dev-team` 在
  应用侧还有另一个同名不同义的定义（本机数据根，与工作区布局无关），两者 MUST NOT 混用。
- **有人用第二次才搬下来**（只管时机，不管准入）：身份串原本在持久层、产物目录名单原本在
  检查域、取消两半原本分散在编排与执行体、架构域那几个路径原本各自在调用方手上——都是等到
  第二个调用方出现才搬到这里。没人用第二次的通用文件助手、通用错误类型刻意不铺，本模块因此
  保持很小。
- **取消只依赖标准库，这是门槛的后果而非风格偏好**：拿不到异步运行时的通知 / 订阅通道，
  取消只能写成「共享一个原子标志 + 需要时按固定间隔来查」。异步的等待（停等、应答）仍走
  编排侧原有通道，两条路并行，谁也替代不了谁。

## 不变量

- 拼路径的函数**只做字符串运算**：不读盘、不建目录、不起子进程。某个目录在不在，由调用方
  自己判断，所以「根目录还不存在」也能正常拿到路径。
- 上层 MUST NOT 自己拼目录名和文件名：配置文件名、报告槽位的三个后缀、架构域的五层目录，
  都只在这里出现一次。
- 报告槽位只有三个取值（`Test` / `Baseline` / `Archi`），只在本进程内用，不做序列化、不进
  进程间调用；检查侧的两个执行体 MUST NOT 接受 `Archi` 槽位（漂移报告与检查报告分开存放）。
- 取消标志的相等看的是「是不是同一个标志」（共享同一个底层原子才相等），不看「当前有没有
  被置上」；置上可以重复，重复置没有副作用。
- Windows 保留名的判断逐层进行、ASCII 大小写不敏感：每一层里第一个 `.` 或 `:` 之前的部分
  命中就算（扩展名、`:` 之后的流名都不改变结论），行尾空格先按 Win32 的归一规则剥掉。

## 契约面

契约词汇（JSON Schema + `x-function`）只能表达值的形态：没有「路径」这个位置，也没有
「引用一个已经存在的类型」的位置——`$ref` 只能指向本模块自己的 `$defs`，生成物是照着它
**新建**类型。公开面因此分成两半，操作名与逐条语义只写在 schema 里，本节只记为什么：

- **只涉及标量的操作进契约面**：它们在契约词汇里有精确形状，生成物能据此做编译期签名核对。
- **其余操作留白**：入参是路径、返回是路径的拼路径函数，返回借用字符串的派生，返回具名类型
  的派发，以及零返回的设置动作——硬写进契约，两侧签名一定对不上（`apiSignatureMismatch`
  永远是红的），所以不进契约面。要补齐得先扩契约词汇（加路径位、加已有类型的引用位），
  而不是把判据放松。构造器按纪律不进契约，两类都不计。

`owner` 键填的是「这个方法挂在哪个类型上」或「这个函数在哪个子模块」——它唯一的用处，是在
生成物里做编译期签名核对时拼出 `<owner>::<op-id>` 这个限定写法。所以填类型名或子模块名，
不填 FQN。

## 类型

四个只在本进程内传递的类型（布局结果 / 报告槽位 / 取消标志 / 取消句柄）不进 `$defs`：它们
不做序列化、不进进程间调用，也不出现在任何已声明的操作签名里——按「第一层 `properties` 加
经 `$ref` 能到达的那些类型」这个公开面范围，本模块的 `$defs` 是空的。它们是路径结果与取消
信号的容身之处（只在进程内传，不出去），形状由代码负责，契约不管。

因此本模块的生成物只有签名核对、没有类型定义；入口也没有接生成物，两者之间因此没有编译期
绑定。**不接不是「差一行导出」**：签名核对要拼出 `<owner>::<op>` 的限定写法，而契约里的操作
签名表达不了**方法的接收器**——带 `&self` 的读法写进契约，只会得到一条类型对不上的见证行，
补导出面解决不了它。本模块不会为了「让生成物能编译」多开导出面，也不会为了让见证行成立去改
方法的形状；「契约怎么表达接收器」留给独立裁决。
