### 零映射对的成因（三条设计依据 + 一条实测核证）

1. **无待测功能来源**：design 的「公共函数 / API」与「类型定义」两处为整段省略注释（原话：`scan::owner::{OwnerIndex::build, owner_of}`、`scan::scan`、`drift::check`、`api::{findings, index_entries, compare}`、`archi_graph` / `archi_module` / `archi_search` / `archi_drift` / `archi_file_tree` 的签名与行为零变化；`ArchiElement` / `ArchiDriftReport` / `ArchiFileEntry` / `IndexEntry` 形状零变化），「路由 / API 设计」亦整段省略（零新增 IPC / HTTP / CLI 子命令）。按本相位纪律 `#### 待测功能` 只登记 design 明写的命名单元，MUST NOT grep 源文件导出声明或虚构条目 ⇒ 10 个模块均无 `#### 待测功能` 行可写。
2. **设计与提案明令零测试代码**：`proposal.md`「测试文件」表两行均为**无**，理由为「仓库模型属数据资产，`desktop-archi-api-check` 明写 MUST NOT 把本仓模型与契约塞进 crate 语料、基线表亦明写不写进断言（易随元素增减漂移）」；`design.md` 事实校准 11「零测试面」同结论，D10⑥ 把「不新增 / 改写任何测试」列为明确不做项。为两行元素数据或 `53 / 120`、`12 / 29` 写断言，会把「报告数与实测对拍」的责任从 change 留痕搬到脆弱常量上（`desktop-archi-api-check/spec.md:104`「基线不写进断言，断言只锚定『实现期留痕的实测表与报告逐项相等』」）。
3. **数据 / 文本 / 生成物 / 配置资产无同前缀测试文件形态**：`06-frontend.toml`、`INDEX.toml`、`0001-model-granularity.md` 与两份 delta `spec.md`、`package.json`、`tauri.conf.json`、`reports/archi/*.json|*.md` 在既有布局下均无 `*_test.toml` / `spec_test.md` / `package_test.json` / `*_test.json` 形态；仓内也没有任何一侧测试以「读取本仓模型 / 裁定记录 / 索引 / 报告并断言其内容」为职责的专用载体。
4. **实测核证（登记事实，不改本稿结论）**：全仓唯一以**真实仓库根**读取模型资产的测试是 `packages/desktop/src-tauri/crates/core/archi/tests/pilot_test.rs` —— `repository_root()`（`:42`，`CARGO_MANIFEST_DIR` 上溯）→ `api_ref(&root, FQN)` → `api::mod::elements_of` → `dto::graph_view(root)`，`diagnostics` 非空即 `Result::Err`（`crates/core/archi/src/api/mod.rs:916–925`），故它是本变更的**既有间接回归锚**（见 `## 不可测试项` 8）。前端全部用例的 `modelFile` 是**字面路径串**，不读盘；`crates/core/archi/src/{docs,dto,drift,scan,parse,api}/**` 的 sidecar 用例与 `crates/tools/archi-api-gen` 的生成 / 检查面全部以 `tempfile` 自造根。⇒ 零 per-file 映射对。
