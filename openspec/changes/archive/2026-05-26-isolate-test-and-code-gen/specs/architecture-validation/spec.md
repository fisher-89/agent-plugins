## MODIFIED Requirements

### Requirement: Import cross-reference validation via TypeScript CLI
The system SHALL provide a `dev-team archi check` CLI command that validates code changes against the C4 architecture model, replacing the Python `archi-validate.py` utility.
The validation engine SHALL:
1. Load the C4 model via `@likec4/core` (replacing `archi_parser.read_model()` + `parse_dsl()`)
2. Build `path_to_element` mapping from element metadata.path
3. Get changed files via git diff (same as existing `--staged` and `--files` behavior)
4. Parse import statements from TS/JS/Python files (same regex patterns, re-implemented in TypeScript)
5. Cross-reference imports against model relationships
6. Generate JSON validation report with violations, warnings, matched elements, unmatched files

#### Scenario: Validate staged files via CLI
- **WHEN** the user runs `dev-team archi check --staged`
- **THEN** the system outputs a JSON report with `violations`, `warnings`, `matched`, `unmatched_files` arrays
- **AND** the report has the same structure as the current `archi-validate.py` output

#### Scenario: Validate specific files via CLI
- **WHEN** the user runs `dev-team archi check --files "src/auth/login.ts,src/auth/logout.ts"`
- **THEN** the system validates only those files against the model

#### Scenario: No model files to validate against
- **WHEN** `models/` directory is empty
- **THEN** the system outputs `{"status": "skipped", "reason": "no model to validate against"}`

### Requirement: architecture agent references dev-team archi check
The `architecture.md` agent prompt SHALL reference `dev-team archi check` instead of `python plugins/dev-team/utils/archi-validate.py`.

#### Scenario: Agent validate mode updated
- **WHEN** the architecture agent enters VALIDATE mode
- **THEN** it runs `dev-team archi check --staged` instead of `python plugins/dev-team/utils/archi-validate.py --staged`

## REMOVED Requirements

### Requirement: Cross-reference via Python archi-validate.py
The Python `archi-validate.py` utility SHALL be removed. Its functionality is fully replaced by `dev-team archi check`.

## ADDED Requirements

### Requirement: TypeScript import parser preserves Python parser behavior
The TypeScript import parser in `lib/c4-cross-ref.ts` SHALL produce the same import target lists as the Python `_parse_js_imports()` and `_parse_python_imports()` functions for identical input files.
The regex patterns SHALL be translated from Python to JavaScript with behavior-identical semantics.

#### Scenario: TypeScript imports parsed correctly
- **WHEN** `lib/c4-cross-ref.ts` parses `import { x } from './path'` in a .ts file
- **THEN** it extracts `./path` as the import target, same as the Python parser

#### Scenario: Python imports parsed correctly
- **WHEN** `lib/c4-cross-ref.ts` parses `from .module import X` in a .py file
- **THEN** it extracts `.module` as the import target, same as the Python parser

#### Scenario: Relative path resolution preserved
- **WHEN** a file `src/auth/login.ts` imports `'../shared/utils'`
- **THEN** `lib/c4-cross-ref.ts` resolves it to `src/shared/utils`, same as the Python `_resolve_import_to_path()`

### Requirement: Cross-reference report format backward compatible
The JSON report generated by `dev-team archi check` SHALL have the same top-level keys as the current `archi-validate.py` report: `timestamp`, `commit_diff_hash`, `changed_files`, `matched`, `violations`, `warnings`, `unmatched_files`, `model_changes`, `status`.

#### Scenario: Report format matches Python output
- **WHEN** both `dev-team archi check --staged` and `archi-validate.py --staged` are run on the same staged diff
- **THEN** both reports have identical keys and equivalent data (violation types, warning types, matched element FQNs)
