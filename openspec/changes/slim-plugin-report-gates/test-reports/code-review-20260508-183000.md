### Warnings (WARN)

> Should fix, but not blocking.

#### [WARN-1] plugin/hooks/pre-tool-skill.py:104-108
- **Category**: Security - subprocess with shell=True
- **Description**: The `subprocess.run()` call uses `shell=True` which can be risky if any part of the command is user-controlled. While the command is constructed from internal paths, this pattern should be reviewed for potential command injection if paths are ever derived from external input.
- **Current Code**:
  ```python
  result = subprocess.run(
      ["python", compliance_check_path,
       "--change", change_name, "--project-root", cwd, "--json"],
      capture_output=True, text=True, timeout=30, shell=True
  )
  ```
- **Suggestion**: Remove `shell=True` since a list of arguments is already provided. The `shell=True` is unnecessary and adds risk. On Windows, the memory note suggests `shell=True` is needed for PATH resolution, but `sys.executable` should be used instead of `"python"` for reliability.

#### [WARN-2] plugin/utils/lint-runner.py:272-280, 319-327, etc.
- **Category**: Security - subprocess with shell=True
- **Description**: Multiple subprocess calls use `shell=True` with string commands constructed via `" ".join(cmd)`. This is generally safe as the commands are internal, but the pattern is inconsistent with the list-based approach used elsewhere.
- **Suggestion**: Consider using list arguments without `shell=True` where possible, or document why `shell=True` is required (Windows compatibility).

#### [WARN-3] plugin/utils/test-runner.py:186-192, 242-249
- **Category**: Security - subprocess with shell=True
- **Description**: Similar to lint-runner.py, subprocess calls use `shell=True` with joined command strings.
- **Suggestion**: Same as WARN-2 - consider using list arguments or document the requirement.

#### [WARN-4] plugin/utils/step-report.py:42-45
- **Category**: Security - Path Traversal Risk
- **Description**: The `save_step_report()` function constructs a path using `change` and `task_id` parameters without validation. If these parameters come from user input, they could potentially contain path traversal sequences like `../`.
- **Current Code**:
  ```python
  reports_dir = os.path.join(
      project_root, "openspec", "changes", change, "reports"
  )
  ```
- **Suggestion**: Validate that `change` and `task_id` do not contain path traversal sequences. Consider adding a check like:
  ```python
  if ".." in change or "/" in change or "\\" in change:
      raise ValueError("Invalid change name: path traversal detected")
  ```

#### [WARN-5] plugin/utils/report-chain.py:36-38
- **Category**: Security - Path Traversal Risk
- **Description**: Similar to WARN-4, the `check_report_chain()` function uses `task_id` in path construction without validation.
- **Suggestion**: Validate `task_id` contains only alphanumeric characters or known safe patterns.

#### [WARN-6] tests/test_error_to_task_flow.py:126-132
- **Category**: Test Quality
- **Description**: The integration test runs the hook as a subprocess but doesn't check `result.returncode` before parsing stdout. If the hook crashes, `json.loads(result.stdout)` will raise an exception that masks the real error.
- **Suggestion**: Add a check for the return code or stderr before parsing:
  ```python
  if result.returncode != 0:
      self.fail(f"Hook failed: {result.stderr}")
  ```

#### [WARN-7] plugin/utils/report-chain.py:50-51
- **Category**: Logical Error - Timestamp Comparison
- **Description**: The timestamp ordering check uses `timestamps != sorted(timestamps)` which requires strictly increasing order. However, ISO 8601 timestamps with second precision could have equal timestamps if steps run quickly, causing false failures.
- **Current Code**:
  ```python
  timestamps = [r["timestamp"] for r in reports]
  if timestamps != sorted(timestamps):
      return False, "Report timestamps out of order"
  ```
- **Suggestion**: Use `<=` comparison instead to allow equal timestamps, or ensure timestamps have millisecond precision:
  ```python
  if timestamps != sorted(timestamps, key=lambda x: x):
      # Check for decreasing order only
      for i in range(len(timestamps) - 1):
          if timestamps[i] > timestamps[i+1]:
              return False, "Report timestamps out of order"
  ```
